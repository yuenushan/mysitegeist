Sitegeist vs 终端 Agent：网站访问方式对比

数据：本机 sitegeist 扩展 IndexedDB 中 16 个真实会话、493 次工具调用实测 + src/tools 源码走查 · 2026-10-05

01结论

终端赢在快、省、准、可批量；sitegeist 赢在登录态、动态渲染、反爬穿透、人机兜底。不是二选一：最优姿势是终端 agent 通过 sitegeist MCP 直接调度浏览器——本报告的数据就是终端 agent 读 sitegeist 的 IndexedDB 得到的。

终端 agent（search_web / fetch_web / curl）

  • 省：一次 fetch = 整页 markdown（闲鱼同主题实测 3.3M tokens，终端路径估算 5–15 万）
  • 快：可并行，无页面等待与 LLM 往返
  • 准：API/正则/脚本，落盘可复现
  • 搜索一步到位，不用进 bing 解析 DOM
  • 无登录态：闲鱼 / 12306 / 内网 SSO 拿不下来
  • 无 JS 渲染：SPA 抓到空壳
  • 过不了反爬：403 / 滑块 / 5 秒盾
  • 不能交互：点按钮、填表单、多步流程

Sitegeist（真实 Chrome 内的 agent）

  • 登录态红利：闲鱼 9 次导航畅通；12306 勾选乘车人「陈京」成功
  • 内网直达：kdb.corp / grafana.corp 带 SSO cookie 直接可操作
  • 过反爬：百度/必应 SERP 直接可读可解析
  • JS 渲染 + 视觉 + 人在旁兜底（验证码/扫码）
  • 贵：3 个会话烧掉 3.3M / 1.2M / 29.7M tokens
  • 慢：每步一次 LLM 往返 + 页面等待
  • 脆：手写选择器 + sleep 轮询，超时 ×6
  • 无批量原语：关标签页竟用了 191 次 repl

05组合决策树

一句话：要登录态/渲染/看图/人在场 → sitegeist；要快/批量/静态 → 终端；fetch 拿到空壳 → 升级走浏览器。

需要登录态、JS 渲染、看图、或需要人兜底（验证码/付款）？ ├─ 是 → Sitegeist （真实 Chrome + cookie + 截图，贵但能干成） └─ 否 → 终端 （search_web / fetch_web / curl，便宜快准） └─ fetch_web 拿到空壳 / 403？ └─ 升级 → sitegeist MCP （navigate → repl → extract_document，终端侧直接调度扩展） # 量化预期：把 338 次手写 JS 压成 waitFor + 元素概览 + ref 交互等少量高阶原语， # 头部会话有望从 29.7M tokens 压回 30 万以内（同任务下 ≈100 倍）。
